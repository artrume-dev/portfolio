Product data quality assistant

A chat assistant for a product information management (PIM) system in a large enterprise. It finds and helps fix data quality problems that today are checked by hand.

Intro

problem · use cases

The problem

In a large product catalogue, data quality is checked by hand: duplicates, broken links between products, inconsistent naming and products that exist in one system but not another. It's slow, repetitive and easy to miss.

Use cases

Quality and governance checks

Duplicates, broken relationships, naming conventions, content hierarchy and embargoes.

Gaps between systems

Finding products missing between connected systems.

Product onboarding

Supporting onboarding, and linking "what's in the box" items across SKUs.

Technical details

solution design · principles

This project is in scoping and the client is anonymised, so this section covers the design principles rather than the implementation.

How it will work

  1. Someone asks the assistant in plain language, for example to check a product range for duplicates or missing links.
  2. The assistant runs the relevant data quality checks and reports what it found.
  3. For each problem it proposes a fix.
  4. A person reviews and approves the fix before anything in the PIM changes.

Design principles

The assistant proposes; people approve
Product data feeds other systems and channels, so no change is applied without a person approving it.
Measured against today's process
Success is judged against the current manual checks, not against a demo.
Built with the agent factory
It will be built in Claude Code using the same spec, slice and review process as the agent factory.
